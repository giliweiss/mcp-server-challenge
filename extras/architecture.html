Tool-by-Tool Flow

Each tool keeps the context small by returning only the data the model needs.

get_device_telemetry(device_id)
  1. AI calls the tool with a device ID.
  2. Device ID is validated by format and allowlist.
  3. Telemetry service reads the latest device snapshot.
  4. Returns voltage, current, temperature, and power.
calculate_efficiency_anomalies()
  1. AI calls the fleet-wide anomaly tool.
  2. Anomaly service reads 48 readings per device.
  3. Compares recent and historical power averages.
  4. Returns a summary plus the top anomalous devices.
reboot_device(device_id)
  1. AI calls the tool with a device ID.
  2. Device ID is validated before action.
  3. Reboot service checks anomaly status and cooldown.
  4. Returns either command sent or a structured rejection.

Key Files

The implementation is intentionally small: one MCP registration layer, three service modules, and in-memory data.

mcp-config.json / .cursor/mcp.json Starts the project virtual environment MCP CLI with run main.py.
fleet_management_server.py Registers devices://fleet-config and the three MCP tools.
device_validator.py Protects all device-specific tools with strict input validation.
services/ Contains telemetry lookup, anomaly calculation, and reboot guardrails.
fleet_data.py Loads config and builds deterministic telemetry history for tests and demos.
tests/ Covers service behavior plus MCP protocol registration and tool calls.
